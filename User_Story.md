
### Epic 1: The Automated Smart Board Engine (The Happy Path)

**User Story 1: Secure Session Ignition**

> **As a** Faculty Member,
> **I want to** unlock the smart board using a 6-digit OTP generated by my biometrically secured mobile app,
> **So that** I can securely start my class session and ensure no one else can spoof my attendance records.

* **Acceptance Criteria:**
* The board must reject any OTP that doesn't match the server's generated code for that specific room's hardware fingerprint.
* Upon success, the board must sync its local clock with an NTP server to calculate the `clock_skew`.
* The board must instantly write the `session_id` and `session_secret` to the encrypted local Isar database for crash recovery.



**User Story 2: The 2-Minute QR Sprint**

> **As a** Faculty Member,
> **I want to** press a "Start Attendance" button to trigger a 2-minute countdown with a rapidly changing QR code,
> **So that** my students can mark themselves present quickly without eating into my actual teaching time.

* **Acceptance Criteria:**
* The QR code must regenerate every 3.5 seconds using the TOTP algorithm (utilizing the `session_secret` and NTP time).
* A highly visible `02:00` countdown timer must be displayed.
* At exactly `00:00`, the QR generator must terminate, and the screen must automatically transition into Presentation Mode (showing my slides).



**User Story 3: The "Blind" Offline Vault**

> **As a** Student,
> **I want to** be able to scan the smart board's QR code even if the classroom Wi-Fi goes down,
> **So that** I don't get marked absent due to university network failures.

* **Acceptance Criteria:**
* If the board loses Wi-Fi, it must display a non-intrusive "Offline Mode" banner but *continue* generating mathematically valid TOTP QR codes.
* The board must capture local Bluetooth/LAN scans from offline students and queue them in the local Isar database.
* When Wi-Fi returns, the board must silently push all queued scans to the backend server and clear its local cache.

### Epic 2: The Manual Exception Protocol (The Faculty App)

**User Story 4: The Post-Class ID Scan (Latecomers & Dead Phones)**

> **As a** Faculty Member (or TA),
> **I want to** use my mobile app's camera to scan a student's physical university ID card,
> **So that** I can manually grant attendance to students who were late or forgot their phones without interrupting the smart board presentation.

* **Acceptance Criteria:**
* The mobile app must successfully read the barcode/RFID on the physical student ID card.
* The app must force the faculty member to authorize the manual scan using their device's native fingerprint/FaceID sensor before sending it to the server.
* The app must provide a toggle to mark this manual scan as either "Present" (for a dead phone) or "Tardy" (for arriving late).
* This feature must exist *only* on the mobile app; the smart board must have no manual entry buttons.
