# v5.4 Security Migration Guide: From MAC Spoofing to Cryptographic Trust

## Critical Security Issue Fixed

**Problem**: The previous version used MAC address (`X-Board-MAC` header) as authentication token, which is:
- Publicly visible (not secret)
- Static (never expires)
- Spoofable (easy to intercept and replay)

**Solution**: Implemented proper cryptographic trust model with:
- JWT access tokens (short-lived, 15min expiry)
- Refresh tokens (long-lived, for obtaining new access tokens)
- Encrypted local storage for tokens
- API key as fallback authentication

## Backend Changes Required

### 1. Update Registration Endpoint (`/api/v1/board/register/verify-otp`)

**Old Response:**
```json
{
  "success": true,
  "session_id": "abc123",
  "message": "Device registered"
}
```

**New Response** (must include tokens):
```json
{
  "success": true,
  "session_id": "abc123",
  "api_key": "bk_live_51234567890abcdef...",  // Long-lived API key
  "access_token": "eyJhbGciOiJIUzI1NiIs...",  // JWT (15min expiry)
  "refresh_token": "rt_1a2b3c4d5e6f...",  // Refresh token
  "expires_in_ms": 900000,  // 15 minutes in milliseconds
  "message": "Device registered with cryptographic trust"
}
```

### 2. New Token Refresh Endpoint

Create: `POST /api/v1/board/auth/refresh`

**Request:**
```json
{
  "refresh_token": "rt_1a2b3c4d5e6f..."
}
```

**Response:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "expires_in_ms": 900000
}
```

### 3. Update Authentication Middleware

**Old Way** (REMOVE):
```javascript
// BAD: Using MAC as password
const mac = req.headers['x-board-mac'];
if (!mac) return res.status(401).send('Missing MAC');
// Check if MAC is registered...
```

**New Way** (IMPLEMENT):
```javascript
// GOOD: JWT verification
const authHeader = req.headers['authorization'];
if (!authHeader) return res.status(401).send('Missing Authorization header');

const token = authHeader.split(' ')[1]; // Extract Bearer token
try {
  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  req.boardId = decoded.boardId;
  req.roomId = decoded.roomId;
  next();
} catch (err) {
  return res.status(401).send('Invalid or expired token');
}
```

**Fallback for API Key:**
```javascript
const apiKey = req.headers['x-api-key'];
if (apiKey) {
  // Validate API key against database
  const device = await db.findDeviceByApiKey(apiKey);
  if (device) {
    req.boardId = device.id;
    req.roomId = device.roomId;
    next();
  }
}
```

## Frontend Changes (Already Implemented)

### Files Modified:
1. **`lib/models/isar_schemas.dart`**
   - **Tokens are NOT stored in Isar.** All tokens go exclusively to secure storage (OS keychain).
   - `DeviceRegistration` contains only: `smartBoardId`, `classroomId`, `hardwareId`, `roomName`, `building`, `department`, `capacity`, `registrationDate`.

2. **`lib/services/secure_storage_service.dart`** (NEW)
   - OS keychain via `flutter_secure_storage` (Windows DPAPI / Android Keystore / macOS Keychain)
   - Automatic token expiry checking
   - Secure retrieval of valid tokens
   - **No custom key derivation.** Uses platform-native encryption.

3. **`lib/services/api_service.dart`**
   - `_getHeaders()` now uses `Authorization: Bearer <JWT>` instead of `X-Board-MAC`
   - Added `_refreshAccessToken()` method for automatic token refresh

4. **`lib/services/device_service.dart`**
   - `registerWithOtp()` now extracts and stores tokens from server response
   - `clearRegistration()` also clears secure storage

## Security Improvements Summary

| Aspect | v5.3 (Old) | v5.4 (New) |
|--------|--------------|--------------|
| **Auth Method** | MAC address (public) | JWT + API Key (secret) |
| **Token Expiry** | Never | 15 minutes (configurable) |
| **Replay Attack** | Vulnerable | Protected (token expiry) |
| **MAC Spoofing** | Vulnerable | Not applicable (MAC not used for auth) |
| **Local Storage** | Plain text Isar DB | OS keychain (flutter_secure_storage) |
| **Token Refresh** | None | Automatic via refresh token |

## Migration Steps for Backend Team

1. **Generate JWT Secret**:
   ```bash
   openssl rand -base64 32
   ```
   Add to environment: `JWT_SECRET=<generated_secret>`

2. **Update Registration Endpoint**:
   - Generate API key on registration
   - Generate JWT access token (15min expiry)
   - Generate refresh token
   - Return all three in response

3. **Create Refresh Endpoint**:
   - Accept refresh token
   - Validate against database
   - Return new access token

4. **Update All Protected Endpoints**:
   - Check `Authorization: Bearer <token>` header first
   - Fallback to `X-API-Key` header
   - Remove `X-Board-MAC` header dependency

5. **Test Flow**:
   - Register device with OTP → Receive tokens
   - Make API call with JWT → Success
   - Wait 15min → JWT expires
   - Call refresh endpoint → Get new JWT
   - Make API call with new JWT → Success

## For IT Admins: Re-registration Flow

If a device needs to be re-registered (e.g., OS reinstall):
1. Device boots → Shows registration screen
2. Admin enters room ID + requests OTP
3. Admin receives OTP (email/SMS)
4. Admin enters OTP → Device registers
5. **Backend revokes old tokens** and issues new ones
6. Device stores new tokens securely

No deadlock possible: Even if old MAC exists in DB, new registration with valid OTP will force re-register.
